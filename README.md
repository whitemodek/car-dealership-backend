# Car Dealership Backend

Go-бэкенд для сайта автосалона с единым каталогом новых автомобилей и
автомобилей с пробегом. REST API для публичного сайта и интерфейса сотрудников.
Стек: Go 1.26, PostgreSQL 17, pgx, Docker Compose, OpenAPI 3.0.

## Сейчас реализовано

- Каталог: модели, комплектации, VIN, new/used, фильтры, сортировка, пагинация,
  фотографии по HTTPS-ссылкам, черновики и публикация.
- Сотрудники: администраторы и менеджеры, bcrypt, непрозрачные Bearer-сессии,
  срок действия 12 часов, отзыв и отключение сотрудника.
- Заявки на покупку, обратный звонок и тест-драйв; согласие на обработку
  контактов, назначение менеджера и контролируемые переходы статусов.
- Брони: срок действия, подтверждение, отмена, истечение, идемпотентность,
  транзакционная защита от одновременного бронирования.
- История цен, оптимистическая блокировка редактирования, аудит и outbox.
- Worker: истечение броней, очистка истёкших сессий, подписанные webhooks
  с повторными попытками и фиксацией недоставленных событий.
- Проверка конфигурации, HTTP/SQL-таймауты, корректное завершение, безопасные
  JSON-логи, request ID, readiness, CORS, ограничения запросов и тела.
- Миграции с контрольными суммами, тесты на настоящем PostgreSQL, проверка
  OpenAPI и соответствия HTTP-ответов контракту, CI и Docker.

Архитектурные решения и границы: [ARCHITECTURE.md](ARCHITECTURE.md).
Полный контракт: [api/openapi.yaml](api/openapi.yaml), можно открыть в Swagger Editor.
Эксплуатация: [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Запуск

Локальная среда через Docker Compose; для генератора конфигурации нужен Go:

```sh
go run ./backend/cmd/envgen
docker compose up --build -d
```

Генератор создаёт игнорируемый Git файл `.env` со случайным паролем и согласованной
строкой подключения. Пароль не печатается; существующий файл не перезаписывается.
`.env.example` содержит пустые поля для ручной настройки вместо готового пароля.
Не генерируйте новый пароль поверх настроенной БД: её учётные данные меняются отдельно.

Миграции выполняются отдельным контейнером до запуска API и worker.
API доступен на `http://localhost:8080`. Стандартных учётных записей нет.
Создание администратора (Bash, пароль читается без отображения):

```sh
export ADMIN_EMAIL=owner@example.com
read -r -s -p 'Admin password (12+ characters): ' ADMIN_PASSWORD
export ADMIN_PASSWORD
docker compose run --rm -e ADMIN_EMAIL -e ADMIN_PASSWORD api /app/manage create-admin
unset ADMIN_PASSWORD
```

В PowerShell передайте те же `ADMIN_EMAIL` и `ADMIN_PASSWORD` через переменные
окружения текущего процесса. Для запуска вне контейнера:

```sh
set -a
. ./.env
set +a
# Для подключения к локальному контейнеру заменяем только hostname.
export DATABASE_URL="${DATABASE_URL/@db:/@localhost:}"
go run ./backend/cmd/manage migrate
go run ./backend/cmd/manage create-admin
go run ./backend/cmd/api
# В отдельном терминале с тем же DATABASE_URL:
go run ./backend/cmd/worker
```

Для демонстрации на пустом каталоге можно явно выполнить
`docker compose run --rm api /app/manage seed-demo`.
В production команда запрещена. Создаются две вымышленные машины, без клиентов
и паролей. Собственные машины создаются через API сотрудников.

Конфигурация:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| HTTP_ADDR | :8080 | Адрес HTTP-сервера |
| SHUTDOWN_TIMEOUT | 10s | Время завершения активных запросов, максимум 1m |
| DATABASE_URL | обязательно | PostgreSQL URL; в production нужен sslmode=verify-full |
| APP_ENV | development | development, test, production |
| CORS_ORIGINS | пусто | Разрешённые origins через запятую, без завершающего / |
| RESERVATION_DURATION | 24h | Срок брони: 15m–168h |
| WEBHOOK_URL | пусто | HTTPS-адрес получателя событий |
| WEBHOOK_SECRET | пусто | Ключ HMAC, минимум 32 байта, обязателен с WEBHOOK_URL |
| TRUSTED_PROXY_CIDRS | пусто | CIDR только доверенных reverse proxies; по умолчанию X-Forwarded-For игнорируется |

`GET /health/live` возвращает 200, когда процесс принимает HTTP-запросы.
`GET /health/ready` возвращает 200 только при доступных PostgreSQL и схеме.
JSON API находится под `/api/v1`. Тело запроса — `application/json`, максимум
64 KiB. Неизвестные JSON-поля отклоняются. Ошибки имеют вид
`{"error":{"code":"conflict"}}` и не раскрывают SQL или контакты.

## Пример бизнес-сценария

1. Администратор создаёт модель через `POST /api/v1/admin/models` и комплектацию
   через `POST /api/v1/admin/trims`.
2. Менеджер создаёт черновик через `POST /api/v1/staff/cars` и публикует через
   `PATCH /api/v1/staff/cars/{id}` с `version` и `publication: published`.
3. Сайт запрашивает `GET /api/v1/cars?condition=used&currency=RUB&sort=price_asc`.
4. Покупатель отправляет `POST /api/v1/reservations` с новым UUID в
   `Idempotency-Key` и явным `consent: true`. В той же транзакции создаётся заявка.
5. Менеджер подтверждает бронь и обрабатывает заявку. При продаже изменяет
   `sale_status` машины на `sold`; активная бронь завершается автоматически.

Менеджер передаёт `Authorization: Bearer <access_token>` из ответа login.
Сессии не используют cookies. Браузерная админка должна держать токен в памяти
или использовать свой BFF, не сохранять токен в localStorage. Фотографии
предварительно размещаются в собственном S3/CDN; API хранит только HTTPS-ссылки,
не скачивает их и не принимает бинарные загрузки.

Цены выражены в минимальных денежных единицах: `250000000 RUB` — 2 500 000 ₽.
Сортировка и фильтрация по цене требуют валюту, чтобы не смешивать разные суммы.
Проданные и снятые машины скрыты публично; забронированные видны с `available: false`.
Срок подтверждённой брони остаётся исходным. Бронь не является оплатой и не
фиксирует цену сделки: условия продажи согласует менеджер.

## Проверки

```sh
go test ./...
go vet ./...
# Передайте TEST_DATABASE_URL из защищённого окружения для отдельной тестовой БД.
go test -count=1 ./...
```

Без `TEST_DATABASE_URL` интеграционные тесты явно пропускаются. Они создают
собственную случайную схему и удаляют только её. Используйте отдельную тестовую БД.
CI генерирует новый случайный пароль БД на каждый job и маскирует его в логах.
Фиксированные учётные данные не хранятся в workflow.
CI всегда поднимает PostgreSQL, выполняет race detector, vet, проверку форматирования,
контракта API, сборку и govulncheck. Контейнеры также проверяются отдельным job.

Опциональный нагрузочный smoke-тест: `LOAD_TEST=1 TEST_DATABASE_URL=... go test
-run TestCatalogLoad -v ./backend/tests/integration`. Условия и ограничения
измерений описаны в [docs/PERFORMANCE.md](docs/PERFORMANCE.md).

Перед реальным внедрением нужно настроить TLS, резервные копии, доступ к БД,
политику хранения контактов, мониторинг и внешние интеграции под конкретный салон.
Платежи, кредитование, 1С/DMS, бинарные загрузки фото и frontend не входят в эту версию.
